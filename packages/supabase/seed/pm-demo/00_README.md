## How to apply

Run each file as ONE statement (it is one `do $seed$ … $seed$;` block), in order 01 → 03, with a
role that can `set role authenticated` (the Supabase SQL editor / `postgres`). Each block:

1. looks up the org's **active `company_admin` with a Clerk user id** in `core.employees` (read-only)
   and an existing active employee to act as the field tech / installer (Core owns employees; none
   are inserted);
2. sets `request.jwt.claims = {"sub": <that user>, "role": "authenticated"}` and
   `set local role authenticated`, then asserts `public.get_org_id()` resolves to the org;
3. applies the compiled plan with `pm.apply_pack_plan(plan, 'primary')` **only if** the company has
   no ACTIVE primary install (raises if a different pack is installed);
4. creates customers / vendors with `pm.create_customer` / `pm.create_vendor` (names start
   "Demo — "; existing ones are reused by name, so a rerun calls nothing);
5. creates each job only when no `pm.projects` row carries its `ext._demo` key, and builds it out
   through member RPCs and member-writable tables;
6. `raise notice`s a summary (who it ran as by role, rows created this run, totals).

Reruns are no-ops (validated: second run inserts zero rows in every pm/core table). Dates are
relative to `current_date` at run time ("Thursday" = the next Thursday 1–7 days out; the pay-app
period ends on the 25th).

## Real vs sample jobs

`p_is_sample = true` jobs never emit to Books: `emit_job_progress` records a snapshot with
`suppressed_reason = SAMPLE`, billing / deposit requests land `UNISSUED` instead of `EMITTED`,
commitments and approved time are not emitted. Sample jobs also get `core.jobs.external_source =
'merit_projects_sample'` and are deleted by **Projects settings → Remove sample data**
(`pm.remove_sample_data`), and `pm.load_sample_job` returns the first existing sample instead of
creating the pack's own sample. Real jobs are permanent test data.

## What could not be seeded, and why

- **Anything that needs a second approver.** The org has one human user (the company_admin), and
  pm enforces preparer ≠ approver (`created_by` is stamped from the JWT `sub`). So:
  - change orders stay **PCO / COR** (pending) — none approved;
  - billing requests (SOV Pay App #1, the closeout final billing, the flooring and service
    tickets) stay **DRAFT** in the billing queue — `approve_and_emit_billing` would raise
    `PM_SOD_VIOLATION`, so no JOB_BILLING event is emitted;
  - subcontracts / POs stay **DRAFT** (no JOB_COMMITMENT);
  - time entries stay **SUBMITTED** (no rates pinned, no JOB_TIME). JOB_TIME would also be
    suppressed as SEAM_V1 because the org's `entitlements.books_seam_version` is not ≥ 2.
  A second member with an approving role can approve all of these from the app afterwards.
- **What does reach Books** from real jobs: JOB_PROGRESS snapshots (contract value / cost estimate /
  pct) and JOB_DEPOSIT_REQUEST invoice requests (no SoD on `request_deposit`).
- **Technicians:** only existing active `core.employees` are used. Live has the company_admin
  and one other active employee; the other one is the tech / installer on every dispatch, the
  admin takes the builder-lot measure, and some visits are deliberately left unassigned in the
  dispatch queue (Thompson measure, Sorensen tune-up). No employee rows are created.
- Retainage release and job close (`final_billed` guard) need emitted billing, so the closeout job
  stops at **closeout**, not closed.
- Documents / photos (`public.documents`, storage) are not seeded.
