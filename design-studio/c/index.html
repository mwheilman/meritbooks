The idea

Accounting software usually shows everything it knows. This shows only what a person has to decide, and proves each proposal with evidence.

Every screen opens with the decision, not the data. The owner gets a sentence and three answers. The bookkeeper gets a queue sorted by how much judgment each item needs. The controller gets a statement whose variances arrive already explained. The AI never chats. It proposes, it shows its work, and a person approves. Nothing posts without that approval.

The brand does the rest: Syne only where a number or a title has to land, DM Sans for the work, one Electric Blue action per screen, Midnight for structure.

Signature: the evidence strip

Wherever MeritBooks proposes something, it appears in one shape: a 2px Electric Blue rule on the left edge, a header naming who proposed it, then the facts in ruled cells, each with the source it came from.

For bank transactions the confidence score is not a vague percentage. It is the actual matching rule, drawn to scale: vendor 40 + amount 40 + date 20. A bookkeeper sees at a glance which part of the match is weak, here the date, before reading a word.

The left rule is a state language across the product. Blue means a machine proposed it and a person hasn't decided yet. Midnight means a person approved it. No rule means it's posted.

8-point grid

Layout runs on 8: 16, 24, 32, 40, 48, 64. Four-point steps only for tight inline gaps. Owner screens use 12 columns, 24px gutters, 40px margins.

Accounting conventions

Negatives in parentheses, right-aligned tabular figures, cents in the feed and whole dollars on statements, totals double-ruled.

Color discipline

One Electric Blue action per screen. Red only for a covenant or variance that costs money. Slate is used as text on Midnight only, where it passes AA.
